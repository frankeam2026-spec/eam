# 保养、点巡检类型ID与周期

## 已实现

- 既有保养项目、计划设备、周期巡检计划的`typeId`继续使用；周期由服务端根据同租户的类型ID带出并校验启用状态，前端周期改为只读。
- 日常点检计划补充巡检类型选择；计划类型不限制路线项目的类型，班次生成规则不变。
- 保养任务增加`eam_maintenance_task.type_id`；巡检计划增加`eam_inspection_definition.type_id`；巡检任务增加`eam_inspection_task.type_id`，带索引及外键。API返回类型ID，名称和历史周期保留快照。
- 任务生成同步写入类型ID；巡检计划类型停用时停止生成新任务；类型删除补任务引用校验。
- 已被计划引用的类型周期禁止原地修改，需新增类型后更换计划类型。更换周期巡检类型会重置调度锚点，保留合法下次执行时间。
- 类型作为计划／标准选择数据通过choices提供，维护类型仍受原菜单权限控制；停用类型不可新选。
- V59新增字段，V60按现有ID回填任务并统一计划周期。旧日常点检的类型仅能按同租户唯一1日类型补齐；无法确定则保留未关联，不能凭名称猜测。历史任务周期快照不改写。
