# 条件条筛选与公共表格统一

日期：2026-10-15。依据用户确认的台账方案及后续“应用到其他模块”“统一table样式”的授权。

## 已实现

- 公共 FilterConditionPopover 使用 ElPopover，320px字段列表／普通字段编辑，日期字段420px；无整页遮罩。按钮靠右对齐，条件标签靠左对齐，交给原生Popper处理视口边界。
- FilterFieldInput 统一文本、多选、树形、日期及数值控件；沿用 advancedFilters 的草稿、准备、校验、匹配和标签函数。内部控件弹层挂在父浮层内；外部点击丢弃草稿，应用空值删除，字段唯一。
- useConditionPopover 统一触发位置、编辑字段和确认更新；AppliedFilterChips 可选编辑、独立删除、长标签省略及悬浮完整值，默认调用行为不变。
- 设备台账、维修工单、保养任务、点巡检任务、用户管理、出库管理、异常／维修计划列表接入公共浮层，移除相应重复列筛选入口。共享模块中的标准／计划及角色等简单列表保持其既有轻量控件，不额外添加浮层。
- 台账状态页签由唯一已应用条件推导。单状态对应页签，多状态对应全部设备；再次点击全部设备也清除状态条件。左树作为独立范围标签，可移除、重新展开定位；重置保留范围。
- 台账请求不再传旧状态等裁剪参数；保持既有关键词、授权接口及最多10000条的原有加载范围，不改数据库／服务端权限。
- 出库旧链接、异常／计划个人偏好的旧列条件读取时并入唯一条件集合，同字段以新条件优先，后续保存不再写入重复列条件。
- AppBusinessTable 默认 borderMode=header：保留ElTable原生border以支持列宽拖动，公共样式仅隐藏表体竖边框。原生排序图标、已有业务排序逻辑、勾选和固定操作列规则不变，不为无排序实现的列添加无效按钮。
- 删除无调用方的 AdvancedFilterDrawer 及旧宽弹窗模式；更新UI-26B、UI-26C。

## 已验证

- npm run build：通过（含vue-tsc）；筛选规则脚本 scripts/test-advanced-filters.mjs 通过，覆盖包含、多选、数值单边、日期结束日边界、树形下级、标签及旧条件兼容。
- 台账浏览器：文本搜索字段／应用／取消、状态标签和页签单选多选同步、再次点击全部设备清除状态、独立删除、数值反向区间错误及单边条件、日期快捷区间、类别树选择、无结果保留条件。
- 左树范围：选择机加工一部显示范围标签与8条结果；重置保留范围，收起后点击标签重新展开定位；移除可清除范围。
- 台账文本“数控”：列表3条，实际下载CSV3条，全部包含关键词。
- 维修、保养任务、周期巡检任务、用户、出库、异常列表分别实际打开公共浮层并应用文本条件，标签生成正常；维修无匹配时展示空态，用户姓名“林”筛出1条；出库条件写入路由查询。
- 公共表格DOM：维修表格的border模式为header，表体边框透明，存在原生排序caret。
- 列宽实际拖动：台账设备编号190px到230px，确认生效后恢复190px。
- 1280×720：普通条件编辑320px，标签附近展示不超界；1440×900：字段列表320px，高356px，无遮罩。检查后已恢复实际窗口尺寸（1280×720）。
- 本地服务恢复启动：MySQL3306、后端8080、前端5177；后端现有47项迁移校验通过，无新迁移。
