## 不应该枚举化

- 设备类别、故障类型/原因、保养类型及其他客户可配置基础数据：使用既有基础数据/字典实体。
- 国际化展示文案、CSV 标题及错误文本：使用消息键/展示映射，不作为持久化状态权威。
- SQL 列名与前端展示字段：字段映射/白名单；不混同业务状态。
- 任意历史 JSON 自定义字段：维持有界动态数据模型，不将客户数据编译为 enum。

## 执行与门禁

1. **现成枚举复用**：先清除 `RequisitionService` 中重复的申请状态字面量，覆盖受影响分支并测试。
2. **独立业务域**：逐域确认完整编码和 API/DB/通知/SQL/测试调用链，提交独立可回退 PR，不做全仓盲替换。
3. **反回退**：每个受控类型建立编码兼容与非法编码反例；有真实 SQL 的领域运行隔离 MySQL 测试。静态门禁须先核对存量并证明反例能被拒绝。
4. 每批 PR 必须同时说明已处理和仍存在的裸编码、旧数据迁移要求（本轮预期无迁移）、中文注释与 CI 实际结果。
