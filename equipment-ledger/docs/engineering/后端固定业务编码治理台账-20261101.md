## 不应该枚举化

- 设备类别、故障类型/原因、保养类型及其他客户可配置基础数据：使用既有基础数据/字典实体。
- 国际化展示文案、CSV 标题及错误文本：使用消息键/展示映射，不作为持久化状态权威。
- SQL 列名与前端展示字段：字段映射/白名单；不混同业务状态。
- 任意历史 JSON 自定义字段：维持有界动态数据模型，不将客户数据编译为 enum。

## 执行与门禁

1. **现成枚举复用**：先清除 `RequisitionService` 中重复的申请状态字面量，覆盖受影响分支并测试。
2. **独立业务域**：逐域确认完整编码和 API/DB/通知/SQL/测试调用链，提交独立可回退 PR，不做全仓盲替换。
3. **反回退**：每个受控类型建立编码兼容与非法编码反例；有真实 SQL 的领域运行隔离 MySQL 测试。静态门禁须先核对存量并证明反例能被拒绝。
4. 每批 PR 必须同时说明已处理和仍存在的裸编码、旧数据迁移要求（本轮预期无迁移）、中文注释与 CI 实际结果。

本台账是活文档，后续按确认的文件/行号补充，不用推测的次数或百分比冒充全仓完成率。

## 权限动作迁移

- 基础资料、计划选择器、知识助手、工作台与管理分析、设备异常与计划维修、设备标签、设备导入的固定权限动作改用 `PermissionAction`。字符串动作入口仍服务历史与尚未迁移的调用方。
- 系统权限服务与角色管理从同一枚举生成动作编码。历史 `view` 与 `create` 仍按原规则匹配，角色接口与授权关系表继续保存原中文编码。
- 前端角色菜单、授权编辑器和默认查看动作引用 `permissionActions.ts`，显示名称继续由 `enumLabel` 处理。
- 设备台账、维修、保养、点巡检、库存与工作流已收口固定权限动作。任务与单据内部使用枚举；现有仓库和公司授权的字符串入口接收枚举的兼容编码。设备和工作流的 HTTP 动作参数维持原默认值、菜单白名单和错误口径，前端权限判断复用对应动作键。
- `PermissionActionArchitectureTest` 随 Maven 单元测试运行，覆盖上述业务包的直接权限调用，包含跨行、三元表达式及仓库授权。任务动作、业务状态和审计文案继续使用各领域自己的契约。
- 2026-11-19 本地验证：比对前后端角色动作矩阵及后端历史菜单动作矩阵，编码一致。隔离 MySQL 验证角色新增、编辑和回读，基础资料回退与门禁通过回归测试；前端类型检查、权限及国际化测试通过。
- 六模块收尾验证：363 项后端单元、契约及架构测试通过；隔离 MySQL 的 15 项用例覆盖设备修改权限、维修审批、保养验收、点巡检计划与设备范围、库存金额与仓库授权、工作流租户及脚本动作权限。前端类型检查及 6 项权限和国际化测试通过。

## 二态启停标记

- `ActivationStatus` 定义数据库和写入接口使用的 `1/0`，以及旧列表和导出使用的「启用／停用」。基础资料、用户、角色和组织的响应共用该转换，用户、保养、点巡检和库存列表的 SQL 使用同一套文本。读取时仅 `1` 表示启用，写入继续执行各接口原校验。
- 授权动作仍由 `PermissionAction` 表达。库存批次、效期的「启用／未启用」是另一套现有筛选值。Maven 定向检查 Java 和查询代码中重复写入的「启用／停用」二态转换。
