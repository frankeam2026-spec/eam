# 发送记录保留与清理

## 实施前数据库审查（ENG-44至ENG-51）

范围仅限通知发送日志及查询，不变更维修、点巡检、保养主表。当前`eam_notify_message`保存站内消息和来源防重键，`eam_notify_delivery`同时承载投递状态与详细日志。现有站内消息读取和扫描防重依赖发送日志，不能直接删除。

- `eam_notify_retention`：租户一对一保留配置，租户主键；成功保留天数默认90、异常保留天数默认180，范围1至3650天；独立行版本控制并发。查看复用发送记录查看权限，修改复用通知渠道编辑权限。
- `eam_notify_receipt`：通知一对多渠道处理凭据，主键(message_id,channel)，外键关联通知。保留终态和实际成功时间，不保存错误长文本与重试队列字段。仅清理时写入，永久保留到消息生命周期另行设计，用于防重和站内可见性，不作为历史日志页面数据源。
- `eam_notify_delivery`：补记录生成时间和最后变更时间，前者从通知生成时间回填；成功记录按真实发送时间保留，旧异常时间无法可靠回填，统一从迁移时重新计算异常保留期，不猜测。索引(status,updated_at,id)服务清理；通知补(tenant_id,created_at,id)服务日期范围分页。
- 查询路径：租户＋生成日期范围＋可选状态、渠道、业务类型、接收用户、关键词，在数据库筛选、计数、排序和分页。日常／周期通过检查任务真实kind关联区分，不通过标题猜测。
- 清理路径：每日北京时间03:15分批查询终态候选，事务内按消息ID升序锁消息，再锁并复核发送记录，先写渠道凭据再删除明细。投递创建也锁同一消息，避免清理与扫描并发重建。自动重试中的FAILED、PENDING、SENDING均不删除。
- JSON：不新增JSON字段。保留既有历史模板参数，与本轮日志清理无关。
- 迁移采用新增V98；不删除既有表和列。上线前备份，核对日志数量与外键。回退需保留新凭据读取和防重兼容，已清理的日志明细只能由备份恢复，不能退回不认识凭据的旧发送程序。

不自动删除站内消息或业务记录，不提供手动一键清空，不实现外部归档。保留配置缩短后，下次定时清理按新期限处理，界面明确说明。
