# 设备台账列表优化（2026-10-21）

## 范围与实现

仅修改设备台账列表，视觉及交互依据根目录 UI-107、UI-108。保留本会话之前的设备编辑独立维护改动。

- 默认列改为8个高频业务字段，增加名称、型号、部门、位置、负责人基础宽度；可伸缩列分配剩余宽度，已保存的拖动列宽优先。已有列显示及宽度偏好不自动覆盖；点击恢复默认时恢复本页默认列及宽度。
- 部门单元格展示完整路径的末级名称，Element Plus Tooltip 在悬浮或键盘聚焦时展示完整路径，屏幕阅读器保留全路径。接口、筛选、排序和导出仍沿用原组织字段与权限范围。
- 页大小默认20，按用户最新要求支持20/50/100，在本浏览器按租户、账号和设备台账页面单独记忆；旧10条缓存、无效缓存、存储不可用时使用20，不阻止查询。
- 使用公共 AppBusinessTable 的 loading/error 能力；本页空态区分加载、无数据、条件无结果、请求失败，错误内嵌重试，失败清理过期计数并保留失败页码供重试。迟到请求不得覆盖新结果及加载/错误状态。
- 清除查询条件保留组织树范围；范围单独清除到全部授权设备。只读账号不显示新增引导。

## 边界

本轮没有数据库迁移、业务接口或SQL修改，未新增前端过滤和分页。原查询参数、数据库权限、筛选、排序、计数及分页继续生效。多语言仅增加本轮词条并保留既有译文。

现有列偏好仍使用原有本地键以兼容旧设置；列顺序拖动、列偏好按账号隔离／服务端同步、返回恢复勾选，以及复制操作收纳未纳入本轮，不能据此宣称已完成所有列表规范。

## 本轮验证

前端新增5项测试，覆盖账号之间的页大小隔离、异常缓存恢复、真实服务端分页参数、过滤无结果、失败页重试与计数清理，以及旧请求失败不覆盖当前结果。完整前端检查包含29项测试、类型、多语言、图标、表格及控件检查。

初轮浏览器检查1920×1080和1280×720，窄屏横向滚动限定在表格内；使用开发服务只读查询验证无结果→清除条件→恢复12条记录，及完整部门路径的键盘提示；当时单账号实测切换10条/页并刷新后保留，再恢复20条/页。没有向开发业务库写入验收数据。截图位于本机 .local-runtime/equipment-ledger-1920.png。

随后按用户要求将选项改为20/50/100：本次定向测试覆盖100条偏好保存与恢复、旧10条缓存回退20，以及列表传入的分页选项；未重复浏览器和大数据验收。

## 后续：全系统分页统一（2026-10-21）

用户进一步要求所有列表采用20/50/100。按UI-109，公共AppPagination统一使用src/utils/pagination.ts的选项，AppBusinessTable及各业务列表、明细、对象选择弹窗的默认值统一20。设备档案、工作中心偏好和待办／出库网址中的旧页大小回退20。标签模板原24条分页、标签打印设备选择原固定10条分页，以及点巡检／保养标准选择原固定5条分页均支持新的选项。首页摘要与通知预览的固定样本数不变。

验证：已有30项前端测试通过，新增3项测试通过，覆盖公共分页切换后回到第1页、旧偏好兼容和标准选择器按100条请求服务端。类型、多语言、图标、表格与控件检查及生产构建通过（仍有既有的大分包提示）。没有执行业务写入；未逐页进行浏览器视觉验收、真实多账号偏好恢复或大数据性能验收。

已知既有问题：SpareInventory仍在前端筛选和分页；WorkCenterService及AnomalyService部分业务查询仍在服务端内存中筛选、计数与分页，不符合数据库分页要求。此次仅调整页大小和分页控件，未修改查询或数据库结构，不能视为已解决上述查询与性能问题。

未验证：三种皮肤与多语言下的完整视觉验收、真实多账号端到端切换、浏览器禁用存储的手工场景、大数据性能。本轮服务请求失败和迟到响应通过组件测试模拟，未中断开发服务制造故障。
