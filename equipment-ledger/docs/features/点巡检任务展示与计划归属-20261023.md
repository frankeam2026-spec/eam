# 点巡检任务展示与计划归属

## 已结束日常点检结果修订（同日后续确认）

日常点检任务新增独立的`修改结果`角色权限及详情能力`canAmendResult`。不继承执行权限或负责人身份，既有角色不自动授权；仍要求任务查看权限及该操作的数据范围。周期巡检不扩展。

`POST /api/v1/inspection/tasks/{id}/amend-result`仅允许已完成／已审核的日常任务，沿用行锁、版本校验、租户隔离及原事务边界。复用检查结果的完整校验和附件权限校验，仅修订检查项、说明及结果附件；原跳过范围、扫码记录、点检人、起止时间、审核结果均保留。保存不重开任务、不新增提交批次、不通知审核、不触碰库存结算或领用记录。设备履历结果摘要同步更新，时间轴追加修改人、时间及变更摘要，事件审计保留修改前后结果。

新增3项业务回归及既有3项访问／删除策略测试通过，覆盖两种终态、原审核与时间保留、异常重算、无权拒绝、数据范围、跨租户、旧版本、必填校验及不重复库存结算／审核待办。前端类型和语言检查、后端构建通过。本轮未对本地业务任务执行实际修订，未进行浏览器交互验收；无数据库结构迁移。

本次范围：日常点检计划生效日期、任务列表和详情；日常及周期巡检任务的组织树筛选。以根目录业务规范同日后续确认作为业务规则来源。

## 实现

- 移除日常安排的独立起算日期控件。保存时`anchor_date`只作为计划`start_date`的兼容镜像；实际调度直接使用计划有效期，忽略旧安排起算日期，不修改历史迁移或重写已有任务。`effective_from`仍限制已结束窗口的补建。
- 任务返回明确的`planId`。列表与详情复用只读计划弹窗，实际读取计划详情接口，由接口校验查看权限；有编辑权限时可继续进入原计划编辑页面，不用任务查看权限替代计划权限。
- 日常任务列表新增默认班次列。对既有列设置执行一次仅新增班次列的兼容处理，保留其他列选择、宽度及查询状态；之后仍可自行设置列。
- 日常任务概览显示快照中的单台设备名称、编号和规格型号，移除应检设备数量。点检人、实际开始、实际完成由独立三列区块承载，窄屏自然换行。列表日常任务的实际点检人同步改为点检人。
- 日常详情暂不挂载关联异常（含处理任务）和关联用料区块。保留原数据、后台接口、库存事务及历史执行逻辑；周期巡检详情保留已有多设备和关联区块。
- 任务列表Repository按任务类型连接对应的日常／周期计划主表，组织树条件和树节点来源使用计划部门ID。权限、队列、扫码设备查询仍使用原任务范围；筛选、计数、排序和分页继续在数据库中完成。

## 本次验证

- 前端7项：安排编辑、单设备任务概览、点检人与实际时间布局、计划实际ID读取及无权查看反馈；类型检查、语言目录及硬编码检查通过。
- 后端9项调度测试通过，包含计划日期边界、旧独立起算日期不再生效、跨夜、休息日及无班次；隔离MySQL两项回归覆盖无独立起算日期保存、任务planId与班次输出，以及日常／周期任务的计划部门与设备部门不同时的实际查询结果。
- 未执行本地业务数据删除或真实点检提交流程；本轮不宣称全模块验收通过。旧历史任务缺失的设备型号或班次不猜测回填。

## 计划／任务列表切换残留修复

用户确认“先2条后3条”是从计划列表切换任务列表时，先看到了原计划记录，再显示任务记录。页面复用期间原记录和总数没有清空，并非这次切换新增了任务。

路由切换时同步清空当前记录、总数、选择和组织节点，撤销旧请求结果的应用资格；公共业务表格接入已有loading属性。相同页面的后台刷新保留当前数据，避免每次刷新清空列表。本次仅修改点巡检列表，不推广其他模块或修改任务生成规则。

新增两项回归通过：新任务请求等待期间不保留旧计划及总数；迟到的计划响应不能覆盖已经展示的任务结果。

## 详情统计栏视觉调整

任务概览改用局部`InspectionTaskMetrics`组件：整条浅色背景、标签在上数字在下，用时在右侧以细分隔线区分，异常与用时复用IconPark公共图标；正数异常／未检使用语义色，0保持普通颜色。细进度条显示已检／应检，更新采用180ms过渡，遵循减少动态效果设置，窄屏自然换行。原统计栏专用样式随替换清理。

编辑时根据当前录入预览已检、未检、异常及跳过数量，不修改保存的数据或提交规则；只读时展示后端原统计。进度分母仍是应检项目，不将跳过当作已检。新增两项组件回归覆盖0值颜色、用时、完成进度、值为0的有效录入、跳过及不变更原保存计数。
