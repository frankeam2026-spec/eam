# 设备编辑分区维护（2026-10-21）

本轮按用户选择的“核心编辑＋独立维护”原型实施，视觉规则以根目录 UI 规范 D-09 为准，不推广到其他模块。

## 已实现

- 核心资料、图片、相关文件、扩展信息集中编辑，右侧提供 BOM／子设备数量摘要及档案入口。保留原有字段及自定义字段能力，新增设备先保存再维护关系。
- 核心字段区域宽度达到 1200px 时三列；1920×1080 显示三列，1440×900、1280×720 显示两列；窄窗口降为一列，长路径及长文本按需跨列。顶部仅一个标题和设备身份，底部固定保存。
- BOM、子设备在各自工作区独立保存，返回时保留未保存的核心资料；本区修改有独立离开确认，路由离开由外层统一保护，避免双重确认。设备档案入口遵守查看权限。
- 新增 `PUT /equipment/{id}/details`、`/{id}/bom`、`/{id}/children`。原整体更新接口继续兼容旧调用；台账编辑使用 details 接口，图片和文件随核心资料保存，上传成功提示明确关联尚待保存。

## 数据及事务边界

没有数据库结构变更或新增迁移。BOM、子设备继续使用既有 `eam_equipment_bom`、`eam_equipment_child`；历史未确认关系沿用专用 legacy 表，未新增 JSON 核心业务存储。

独立关系接口只接收 `{rows:[...]}`，沿用父设备编辑权限、租户范围、真实关联 ID 校验、BOM 正数两位小数、子设备同公司／单父／无循环约束。沿用库存互斥→公司锁→版本更新→关系校验及写入顺序，在同一 READ_COMMITTED 事务中更新父记录版本；失败整体回滚。核心资料保存不替换关系，关系保存不提交核心字段、附件、负责人或扩展字段。

- 前端完整检查：类型、多语言、24 项测试、图标、表格与控件检查通过。新增组件测试覆盖独立保存后保留核心草稿，以及缺失版本不发请求。
- 后端测试与打包：131 项测试通过，其中新增 5 项覆盖旧版本、权限拒绝、锁顺序以及关系清空隔离。
- 业务接口检查仅连接新建的 `eam_editor_test_20261021`，服务为 127.0.0.1:8081。11 项检查通过：分别保存保留另一关系与核心字段、旧版本拒绝、无效数量／物料ID回滚、自关联／循环拒绝、缺失版本拒绝、核心保存不覆盖关系、分别清空关系不影响其他数据。
- 浏览器在隔离服务对应的 5178 前端实测：核心名称草稿→BOM 独立保存→返回保留草稿→继续编辑／放弃修改提示→核心保存成功。开发服务只做只读页面及健康检查。

## 已知问题与未验证

- 既有新库演示数据中，设备9012的部门、位置、单位关联ID为空；验收仅在专用测试库补齐这些测试夹具，未修改开发数据。实际编辑这类设备时仍需重新选择有效关联，未放宽服务端校验。
- 当前本机 MySQL 8.0.44；未在 MySQL 8.4、并发压力、普通账号端到端、三种皮肤与英文长文案下完成本轮完整验收。权限拒绝已有单元测试覆盖，不能替代普通账号的业务验收。
- 前端构建仍有既有大于500kB的分包警告，不属于本次编辑页范围。语言包生成器会改变部分既有日常点检译文，本次保留原译文，仅新增本轮词条，未扩大语言整理范围。
