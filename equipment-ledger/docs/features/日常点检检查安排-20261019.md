# 日常点检检查安排改造与验收

日期：2026-10-19。范围：日常点检计划与任务。四类业务统一任务底层仍按独立计划待实施。

## 已实现

- 一份计划多条检查安排，按设备／项目子集应用；留空表示计划设备或该设备全部已选项目。
- 日、周、月、班次、多时段、固定分钟间隔、人工事件；固定起算、跨夜、休息日、节假日和特殊开工日。
- 指定操作工、操作组、可选排班及跟进负责人；设备级人员覆盖。多人候选由一人开始并原子锁定。
- 操作组新增、成员维护及版本校验；修改仅影响后续生成任务，不重写已生成任务人员。
- 未来7／30天预览，与生成共用计算；最多展示500条、最多计算10万条，超出要求减少设备或频次，不静默截断合计。
- 新建／编辑安排有独立生效时间，避免追溯生成已经结束的时间窗口；调度中断可补齐生效后的遗漏发生。
- 操作工任务页通过分页选择器发起自己有资格执行的人工事件点检，明确选择设备；主管也可从计划更多操作发起。
- 人工事件校验计划版本、候选资格及设备，幂等键重试返回原任务，改变设备或事件时间拒绝。
- 缺排班保留任务并通知跟进负责人；操作工候选不扩展为租户所有用户。
- 单任务及设备时间范围免检，独立“免检”动作权限；记录原因、批准人和时间。已开始或完成不能免检。
- 任务显示检查安排、业务日期、缺人及免检原因；提交、打回、再次提交与审核保留独立历史记录。
- 免检从设备当前事项、团队未完成工作和分析有效分母排除；库存任务有效性及预留清理识别免检终态，不改写库存账。
- 新文案接入简繁英目录；复用Element Plus、公共对象选择器、表格、底栏和字段错误。

## 数据设计

沿用 `eam_inspection_task`、现有执行结果、项目来源、设备及人员关联，不新增独立日常任务主表。

| 数据 | 新增结构 |
|---|---|
| 检查安排 | `eam_inspection_daily_arrangement`，明确频次、起算日、窗口、责任方式、跟进人、生效时间 |
| 周／月日期、班次时段 | `eam_inspection_daily_arrangement_day`、`eam_inspection_daily_arrangement_slot` |
| 候选人员、设备、项目 | arrangement对应的person、equipment、project关联表，保存真实ID |
| 操作组 | `eam_inspection_operation_team`及person关联表 |
| 特殊开工日 | `eam_inspection_daily_workday` |
| 范围免检 | `eam_inspection_daily_exemption`，按设备与应检开始时间匹配 |
| 历次提交 | daily_submission、submission_item、submission_file、submission_review |
| 任务补充列 | 安排ID和名称、业务日期、跟进人、人工事件键、人员来源、免检原因及批准信息 |

迁移：V88、V89、V90、V91。均为新增文件，不改写历史迁移。不清理既有开发任务或库存数据。

安排、人员和频次存入明确列及关系表。已有JSON兼容视图继续作为API组装；新安排不保存为payload。生成任务仍沿用现有项目历史快照，未在本轮重做整个执行模型。

## 接口

沿用 `/api/v1/inspection`：

| 方法与路径 | 用途／权限 |
|---|---|
| 原daily-plans保存与详情 | 增加arrangements、workdays，原计划新增／编辑／查看及版本校验 |
| POST /daily-plans/preview | 未保存内容的无写入预览，逐设备检查范围和项目 |
| GET /daily-operation-teams | 授权计划范围内操作组 |
| POST /daily-operation-teams | 新增操作组，计划新增权限及部门范围 |
| PUT /daily-operation-teams/{id} | 操作组维护，计划编辑范围及rowVersion |
| GET /daily-event-options | 数据库分页筛选当前操作工可发起的安排与设备，任务查看及执行权限 |
| POST /daily-plans/{id}/events | 人工事件，明确equipmentIds、eventAt、idempotencyKey、rowVersion；计划编辑人员或合法候选操作工 |
| POST /daily-plans/{id}/exemptions | 设备／时间范围免检，任务免检权限及范围、计划版本 |
| POST /tasks/{id}/exempt | 单任务免检，任务免检权限、状态、原因及版本 |

“免检”默认授予现有系统管理员角色，其他角色需在日常点检任务权限中明确授予，不因拥有删除权限自动获得。

## 已验证

隔离数据库：`eam_daily_test_20261019`；隔离接口18085（开发身份）、18086（真实会话鉴权）。所有业务回归写入仅发生在隔离库。

- 全新数据库迁移至新增版本，Spring Boot启动成功。
- 核心流程：七天预览、保存回填、按安排生成、开始、旧版本重复开始拒绝、提交、完成后禁止免检、人工事件幂等、免检、字段定位。
- 调度场景：按周、按月、固定间隔、多时段、跨夜及缺排班、特殊开工日覆盖休息日、操作组候选。
- 执行追溯：审核打回后再次提交并通过，保留两次提交和对应审核记录。
- 权限：操作工无计划编辑权限仍可发起已分配设备的人工事件；其他人员看不到该候选且不能伪造发起；操作工无免检权限被拒绝。
- 范围免检：已批准的未来时段在任务生成时生效。
- 操作组成员维护成功，旧版本再次修改返回409；新建已结束时段不会追溯生成任务。
- 计划安排数、任务安排名称及应检日期新增导出列可用；这不等于全量报表对账完成。
- 隔离检查共32项，见[结构化结果](../verification/daily-inspection-20261019/summary.json)。
- 前端类型检查、构建；后端编译与打包；三语言键、参数及前后端目录一致性检查。
- 当前1280×720窗口查看编辑页及预览，首次打开即可显示预览数据；固定底栏可见。

## 未验证与限制

- 未进行一万条任务性能验收、两名操作工真实并发压测、系统断电恢复及库存全链路回归；旧版本拒绝验证不等于真实并发验收。
- 未检查1440×900及移动端；简繁英新增文案尚未完成现场人员校对。
- 项目结果沿用现有选项、数值、文本及图片能力，本轮没有新增多选结果、双人见证、离线提交。
- 人工事件不自动接收PLC、MES或运行小时数据，不控制物理设备开机。
- 日常点检没有独立新增分析看板；本轮调整已有任务字段与分析终态口径，相关全量报表与导出对账尚未验收。
- 周期巡检原有任务流程和页面不改造；四类任务合表、标准统一等仍待实施。

构建通过不代替业务验收，本记录不能作为后续版本的验收结果。
