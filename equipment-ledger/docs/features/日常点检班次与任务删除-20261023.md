# 日常点检班次与任务删除

本轮用户确认：日常点检只按班次生成；周／月休息日均可设置；列表和编辑明细分区；任务删除仅限未执行的未开始、待执行、已过期任务。现行业务规则见根目录《业务场景与领域规则-v1.2.md》2026-10-23补充。

## 实现与结构审查

- `DailyArrangementEditor`直接维护班次，去掉频次选择及其日／周／月／间隔控件。无班次可保存，不生成任务。列表、编辑明细使用独立容器、24px间隔及明细标题底色；班次输入区域限制宽度。
- `DailyInspectionSchedule`供预览和实际生成共用；一台设备、一项安排、一个班次发生生成一条任务。周休息、月休息、指定休息日取并集，特殊开工日覆盖休息规则；跨夜按开始日期判断。保留原生成幂等、计划事务与锁顺序。
- V94在现有关系表`eam_inspection_daily_rest_day`新增`cycle_code VARCHAR(8)`，取weekly或monthly，明确每行的周期。保留租户、计划、顺序、日期序号与原外键；增加周期与日期范围CHECK。按原计划`rest_cycle`回填，不丢弃旧行。`v_inspection_definition`增加两种日历数组的查询投影，核心日历仍使用关系表存储。
- V95将历史空跟进负责人被错误存入的0改为NULL；Repository同步修正空值写入。真实人员ID不改动。
- 原非班次安排保留，停止按旧规则生成；编辑时提示明确配置班次并核对排班。旧slots枚举保留等价读取，保存规范化为shift。废弃人工事件入口移除；旧HTTP入口只返回空选项或明确拒绝，不再创建任务。历史任务与排班解析仍保留所需兼容能力。
- 日常任务列表和详情复用`InspectionTaskDeleteDialog`，删除原因使用Element Plus字段校验。后端共用删除资格判断，在既有行锁、权限及rowVersion校验中复核状态和执行证据。任务采用既有逻辑删除，保留生成标识和审计记录；重新保存计划或定时生成不会恢复同一设备同一班次的本次发生。
- 日常计划删除只由未删除任务阻止，已删除任务不再计入阻止条件。已删除任务历史保留；现有免检记录保护仍生效。周期巡检、保养计划的删除规则未扩大修改。

## 验证证据与边界

- 班次与任务删除阶段：前端相关10项测试及删除弹窗3项测试通过；类型检查、Vite构建和三语目录检查通过。空原因校验使用真实Element Plus错误展示测试。
