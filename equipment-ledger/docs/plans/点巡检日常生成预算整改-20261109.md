# 日常点检任务生成预算整改（第一批）

基线：main `5cc0e03`，PR #54 已合并。本批只修复已审查确认的日常单次生成数量上限，不重复任务创建、人员分配和生命周期服务的抽离。

## 场景与修改边界

旧代码在安排的整组设备之外检查2000条；一个班次的剩余设备会继续写入。旧班次兼容路径没有该限制。修改前499台设备×5班次两条路径均一次生成2495条；兼容路径跨两天还可一次生成4000条。

| 场景 | 实现入口 | 验收 |
|---|---|---|
| 日常安排及旧班次路径 | `InspectionGenerationService.generate` 每次创建前检查 `DAILY_TASK_BATCH_LIMIT` | 每次至多新增2000条，重复任务不消耗新增预算 |
| 日期处理一部分 | 达到预算时退出当前日期的发生遍历，`dayComplete=false` | 保存当天游标，下轮先去重再生成剩余设备，不误推进日期 |
| 恰好完成整日 | 整日循环正常结束后推进日期 | 当天完成2000条后游标到次日，下一次继续下一日 |
| 已存在及已删除发生 | 沿用现有count、发生唯一键和创建服务 | 保留发生标识，不重复任务、关联或生成事件，不恢复删除记录 |
| 周期巡检 | 原100次循环、锚点和索引不变 | 250个周期仍按100/100/50完成，不引入日常预算语义 |
| 并发、异常、租户 | 原计划→调度锁、事务和Repository SQL不变 | 两个生成线程总计创建2条；事件写入失败回滚整个批次及游标；不同租户不能推进计划 |

生产代码只修改现有GenerationService，没有新增Service、DTO、依赖或数据库迁移。没有修改HTTP、快照格式、人员规则、任务状态、事务传播和锁顺序。同步整理本次文件的显式导入及生成边界中文注释。
