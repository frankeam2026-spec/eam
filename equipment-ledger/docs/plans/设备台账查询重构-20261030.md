# 设备台账查询重构

依据：用户确认一起优化EquipmentQueryRepository.list与EquipmentListQuery。范围为设备列表、导出和既有小卓设备查询调用，不推广到其他模块。

| 场景 | 设计与入口 | 验收 |
| --- | --- | --- |
| 旧URL与高级筛选 | Controller边界参数适配，内部使用条件对象、排序与范围类型；普通和高级条件统一为AND交集 | 旧参数/高级条件组合、非法参数、列表默认20及导出500批次分别验证 |
| 权限、自定义字段 | Service取得授权条件；自定义条件和排序显式传递给Repository，复用既有公共实现 | 普通权限/导出权限交集、数值自定义排序真实MySQL分页及稳定次级排序 |
| 字段口径 | 后端不可变字段目录，筛选和排序共用已注册表达式 | 字典更名、购置日期优先值、文本通配符转义、排序别名与未知字段 |
| 列表装配 | 当前页关联数据批量加载；详情既有契约保留 | 负责人、子设备/BOM、历史兼容、位置路径与空页不变，查询次数不随行数线性增加 |

不增加数据库结构、迁移、查询框架或前端交互。JSON只在HTTP边界用于交换动态条件，内部不以字符串贯穿。已有公共筛选接口保留兼容入口，新增结构化入口复用同一编译逻辑。非法参数显式报错；旧普通条件与高级条件同时传入时保留AND交集，不擅自覆盖。

回退：恢复本次查询/参数适配改动，不涉及数据回滚；不修改库存成本、权限权威、数据库事务或业务状态。

## 实施记录

- `EquipmentQueryParameters` 承担旧GET参数适配：高级条件仅解析一次；忽略已存在的树节点和显示标签元数据。普通条件和高级条件均生成不可变条件对象，不相互覆盖。
- `EquipmentListQuery` 使用条件、排序方向和树范围类型；列表页大小为20/50/100，导出独立使用500条批次。字段名称保持字符串以支持已发布的客户扩展字段，不能传入SQL列名。
- `EquipmentQueryFields` 集中登记核心字段表达式、类型和排序别名；`SqlListFilters` 复用原编译逻辑，并保留设备原有的为空／不为空语义。自定义字段继续通过现有类型化扩展值表查询。
- `EquipmentQueryRepository.list` 只编排权限交集、筛选、排序及数据库分页；权限回调不再夹带自定义筛选或排序。排序末尾固定增加唯一ID，列表与导出共用查询。
- `pageRelations` 按当前页批量取得字典及位置祖先、负责人、子设备、BOM和既有兼容记录；详情读取契约不变。不修改或删除快照存储。
- 修复筛选与显示口径不一致：分类／使用状态／来源／单位使用有效关联字典的当前名称；购置日期优先取purchase_date。导出保留普通日期筛选。
