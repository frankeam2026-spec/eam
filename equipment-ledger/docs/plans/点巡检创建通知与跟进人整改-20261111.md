# 点巡检创建通知与跟进人整改（第二批）

基线：main `3381a08`（PR #55）。只处理审查确认的空跟进人及初始待执行通知问题，继续复用已经抽离的创建、人员分配和生命周期服务。

## 需求、实现与验收

| 场景 | 实现 | 验收 |
|---|---|---|
| 开放点检无跟进人 | `DailyArrangementRepository.taskMetadata` 与安排保存保持空白→null | 实际任务字段为null，不产生用户0的inbox或公共通知 |
| 历史跟进人0值 | 创建及生命周期在发送跟进通知前要求正数ID | 无需改写历史任务，也不再为0创建通知 |
| 已过期、不可补检 | `InspectionSupport.executionTodoEligible` 在创建与维护中共用 | 在写公共通知来源前拒绝待执行通知，不依赖事后关闭待办 |
| 正常待执行、已过期可补检 | 同一资格函数核对状态、开始时间、截止时间及allowLate | 仍产生一次待执行通知，重复生成或维护不重复入队 |
| 未到开始时间、免检 | 资格函数排除未开始和免检等状态 | 正式任务状态保持原语义，不生成待执行来源或渠道记录 |
| 有效超期跟进人 | 保留独立的超期跟进规则 | 不可补检也仍可向有效跟进人发送一次超期提醒 |
| 后半段写入失败 | 沿用原生成事务、真实公共通知Repository | 任务、人员、关联、事件、inbox、公共通知、渠道记录及游标一并回滚，随后可重试 |

资格函数是既有Support中的无副作用计算，不新建通用通知框架，不合并日常和周期的发生规则，也不将用户授权混入系统提醒资格。固定状态继续复用InspectionTaskStatus。截止时刻仍使用原有“等于截止时间可以执行”的边界。

生产改动只有上述Support、CreationService、LifecycleService及任务元数据一个字段绑定；同步整理相关显式导入和中文业务注释。没有修改HTTP、数据库结构、任务状态码、调度游标、发生唯一键、事务传播或锁顺序；本批也不回填历史0值。

## 测试证据

环境：Java 21、MySQL 8.0.44，隔离地址`127.0.0.1:3308/eam_idea_quality_test_20261030`。只使用测试专属租户9911095501；测试前证明明确表为空，测试后先清理该租户通知的渠道记录，再按外键顺序清理并断言为空。业务库3306未用于回归。

- 修改前新增8项MySQL场景：4个业务断言失败，证明过期不可补检仍发通知、历史0值仍发送、空值字段为0；3项正常场景通过。免检夹具最初缺少设备外键，补齐真实设备后单独运行通过，未关闭或绕过约束。
- 修改后43项通过、0失败/错误/跳过：资格边界10、MySQL14、预算5、已有生成5、人员分配3、开始资格2、分层门禁4。
- 随后加强原MySQL回滚用例，第一条任务真实产生公共通知及渠道记录后，第二条事件写入失败；单独运行通过，回滚后消息/渠道记录均为0，重试后消息为2条。最终其他生产代码仅补充注释。
- 资格矩阵包含正常、开始/截止相等、过期可/不可补检、未来、免检、过期作废及完成。MySQL覆盖安排和旧班次两条路径，并保留上一批的2000/495续跑、逻辑删除不再生、租户、并发和重试回归。
- MySQL的NotificationRepository由替身改为真实Spy，实际检查inbox、公共通知来源和SYSTEM/EMAIL/APP渠道记录；只关闭实际投递调度器，不外发邮件或App。

复用原Maven及CI入口：`InspectionExecutionTodoTest`进入backend默认测试；扩展的`InspectionGenerationMySqlIT`已在原mysql-integration显式选择列表中，本批没有新增独立脚本入口或降低门禁。

本地命令选择：`-Dtest=InspectionExecutionTodoTest,InspectionGenerationMySqlIT,InspectionGenerationServiceTest,InspectionGenerationBudgetTest,InspectionTaskAssignmentServiceTest,InspectionTaskStartPolicyTest,LayerDependencyArchitectureTest,LayerPackageArchitectureTest`。证据位于主工作区`.local-runtime/reviews/inspection-notice-before.log`、`inspection-notice-exempt-before.log`、`inspection-notice-after.log`及`inspection-notice-rollback-final.log`。

## 交付边界与回退

只证明数据库通知记录和入队行为，不把SYSTEM记录状态当作真实用户已读，也不把EMAIL入队当作实际邮件已送达。没有执行真实账号/浏览器、外部通知渠道及完整模块验收；新增写入预算、创建上下文类型化、预览和生命周期其他风险仍按各自批次推进。

按本批提交回退即可，无结构或数据迁移。回退会恢复错误通知行为。交付前需检查最终diff、中文注释及7项远端CI；单人自审不等于独立审计。
