# 领料草稿类型化重构

日期：2026-10-30。范围为后端质量整改批次0、1的样板，不代表其他库存接口或保养接口已完成整改。执行根目录《后端开发规范 v1.0》。

## 边界与验收追踪

| 场景 | 设计与入口 | 实现 | 验收依据 |
|---|---|---|---|
| 草稿新增、修改及详情 | 保留原POST、PUT及GET路径和`{data: ...}` | RequisitionDraftForm、RequisitionDetail、DataResponse；Service.create/update/detailView | MVC绑定、JSON兼容、实际MySQL保存读取 |
| 服务端权威字段 | 只接收任务、仓库、备注和明细；修改必传版本 | 类型化请求、服务端取得租户/申请人/公司/编号 | 伪造公司与申请人不能改变归属；忽略已登记的旧展示字段 |
| 非法输入 | 保留数量精度、备注长度及500行上限 | DTO校验，内部调用也执行；精确ID/版本反序列化 | 小数ID、溢出、非法数量、缺版本、未知字段返回400并定位字段 |
| 授权及任务资格 | 延续原申请人、任务参与者和仓库授权 | 共用checkAccess与task，维修审批门槛保留 | 非申请人、跨租户、无任务权限、跨公司仓库及未释放报修拒绝 |
| 并发与回滚 | 两个公开Service入口分别建立事务 | 保留库存互斥锁；锁原单→任务→仓库→升序物料；版本条件更新检查影响行数 | 顺序核对、版本冲突、持久化后注入失败验证主单/明细/事件回滚 |
| 详情及金额权限 | 明确主单、明细、预留、出库分配、事件和审批历史字段 | 类型化查询及响应，金额字段显式省略 | 冻结旧查询作测试基线；合并出库只汇总本申请分配，逐字段比较 |

本批不修改数据库结构、库存成本、预留/出库算法、锁粒度或通知机制；没有清空业务数据。

## 调用链变化

原入口：`Controller(Map) → RequisitionService.save(Long, Map) → 任意Map及位置参数SQL → Map详情`。

当前入口：

```java
DataResponse<RequisitionDetail> create(RequisitionDraftForm body);
DataResponse<RequisitionDetail> update(long id, RequisitionDraftForm body);
DataResponse<RequisitionDetail> detail(long id);

// Service公开事务入口，不依赖同类自调用开启事务
RequisitionDetail create(RequisitionDraftForm form);
RequisitionDetail update(long requestId, RequisitionDraftForm form);
RequisitionDetail detailView(long requestId);
```

Service编排权限和事务，RequisitionDraftRepository负责类型化读写；主单与明细写入使用MyBatis-Plus，详情关联查询使用RequisitionDetailMapper及XML。主单、明细为独立Entity；接口使用显式响应模型，不暴露Entity。SQL使用绑定参数和确定的字段，删除了被替代且已无调用方的旧读写方法。

主单读取明确禁用缓存并清理MyBatis会话缓存：现有库存/工作流动作仍通过JDBC更新，同一事务必须立即看到这些变更。通过“先读详情→JDBC改变状态/版本→再读详情”的数据库反例验证；不为此修改全局缓存配置。

关联出库分配按本申请一次读取并按出库单装配，保留原申请范围、排序和金额口径。本记录不据此声称已完成性能验收。

## 兼容及动态边界

- 原有HTTP 200成功、`data`封装、ID及数量字符串、版本整数保持。金额无权限时继续省略字段。
- DATETIME按原查询实际返回的当地日期时间建模为LocalDateTime，保持原无偏移量JSON，不擅自改为UTC事件时刻。
- 仅旧库存可空ID保留空字符串输出，限定在InventoryId序列化注解；不是新接口的通用空值规则。
- 现有前端保存整个详情，允许忽略的只读主单字段及明细展示字段在RequisitionDraftForm的JsonIgnoreProperties中逐项登记；未登记字段拒绝。公司、申请人、状态等即使传入也不能赋给业务对象。
- RequisitionService.detail(long)暂作旧库存动作的Map兼容输出边界，内部调用类型化detailView；新三个HTTP入口不经该边界。其他动作的输入输出尚未批量整改，待样板审阅后按计划推进。
- 旧工作流history返回值在一次明确边界转换为WorkflowHistoryRound；审批平台本身的Map改造不在本批。保养/点巡检执行权限仍调用各自原有服务，由其校验，不重建权限权威。
- ApiError沿用原code/message/fieldErrors协议。真正动态的字段错误使用Map<String,String>；绑定错误增加明细路径，不返回SQL、原请求值或异常堆栈。
