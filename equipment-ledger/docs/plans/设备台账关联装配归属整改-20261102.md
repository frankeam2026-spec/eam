# 设备台账关联装配归属整改

日期：2026-11-02。接续基础资料读取归属整改，本批完成不等于整个设备台账专项结项。

## 实施边界

确认的维护风险：设备查询仓储协调字典、子设备、BOM和历史快照的页级装配；现有 `EquipmentRelationsService.children/bom` 只向该仓储转发，而设备查询服务及导入追加也依赖这一装配。关联展示规则的权威分散在两个层次。

选择复用已有关系Service，不新增Helper、Service或通用框架。该Service原本拥有子设备和BOM用例及主要Repository，把关联读取与维护留在同一业务边界，避免增加一个仅转发的查询层。

| 需求/场景 | 实现与职责 | 验收 |
|---|---|---|
| 设备列表、导出的页级关联 | `EquipmentRelationsService.pageRelations` 直接协调字典和三类关系Repository | 原500条分批、租户条件、展示名称、上级路径及空数据行为不变 |
| 单条子设备、BOM及详情 | 原关系Service入口直接读取并装配，不再转调设备查询仓储 | 新关系在前、历史关系在后；数量精度及历史未知字段保留 |
| 设备主体读取 | `EquipmentQueryRepository` 只保留主体查询、组织投影和既有媒体读取 | 构造依赖7项变3项，不再持有关联仓储和字典仓储 |
| 导入追加 | 现有持锁事务内改调关系Service自身的子设备读取 | 从原新旧关系总数延续排序，不改版本、锁顺序、事务和写入规则 |
| 对象权限 | 列表授权及详情权限仍由原查询Service入口执行 | 无设备或权限拒绝时不读取关联；不能把内部装配能力视为新的授权入口 |
| 防止回退 | 扩展现有数据归属架构检查 | 合法设备仓储通过；含子设备Repository依赖或页装配方法的反例均被拒绝 |

没有修改HTTP接口、数据库结构、Repository SQL或前端。已有Map行投影和历史快照动态字段沿用，本批没有宣称完成关联模型的全链类型化。两个实质修改的Service同步整理显式导入及相关中文注释。
