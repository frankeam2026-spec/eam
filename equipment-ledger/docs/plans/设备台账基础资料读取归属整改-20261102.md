## 边界与职责

确认的维护风险：`EquipmentQueryRepository.pageRelations` 直接持有 `BaseItemMapper`，并维护基础资料上级遍历、租户条件及分批查询。设备查询因此承担了基础资料自身的数据访问规则。

| 场景 | 实现与职责 | 验收条件 |
|---|---|---|
| 分类、单位、使用状态、来源、功能位置及其上级读取 | 现有 `BaseItemRepository.findWithAncestors` 拥有类型化 Mapper 查询；设备查询仅提供引用 ID | 每层限定租户、保留停用项、沿用逻辑删除和500条分批；空输入不查询、循环终止 |
| 台账列表、详情和导出 | 原 Service、设备查询及 HTTP 入口保持不变 | 展示名称、位置路径、关联历史内容、授权与列表/导出过滤语义不变 |
| 防止重新越过数据归属 | 扩展现有 `EquipmentDataOwnershipArchitectureTest` | 真实设备仓储通过；包含基础资料 Mapper 的违规样例被拒绝 |

没有新增类、框架、SQL、数据库迁移或前端改动。没有修改写入流程、事务和锁顺序。回退本批提交即可，无需数据回填。
