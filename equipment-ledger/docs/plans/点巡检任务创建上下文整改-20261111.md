# 点巡检任务创建上下文整改（2026-11-11）

基线：PR #56 合并后的 `c3373147b5d63b2012f73f70cdbe719c4ee1ee75`。本批仅整理生成→创建的内部控制信息，不改 HTTP、数据库结构、调度规则、锁顺序或事务边界。

## 范围与验收

| 场景 | 实现与职责 | 验收条件 |
|---|---|---|
| 单次发生 | `InspectionTaskCreationContext` 明确开始时间、任务班次键、名称和结束时间；安排式发生额外保存业务日期、原排班班次键 | 周期仍按独立锚点推进；日常安排与旧班次保留各自行为 |
| 生成→创建 | `InspectionGenerationService` 传显式上下文；`InspectionTaskCreationService` 解析人员、装配快照及创建关联 | 删除 `adjust()` 及六个隐藏控制键，不把运行上下文写入快照 |
| 免检 | `DailyArrangementRepository` 将原查询直接映射为 `ScheduledInspectionExemption` 只读投影，生成事务缓存一次 | 设备、起止区间、批准优先顺序不变；批准人、时间、原因准确复制 |
| 兼容与可靠性 | 复用现有生成和架构测试，不增加独立 CI 入口 | 跨夜日期、原班次排班、预算续跑、并发去重、通知和失败回滚通过 |

## 改动前后

- 原实现把 `_arrangement`、`_businessDate`、`_rosterShift`、`_windowEnd`、`_eventKey`、`_exemptions` 写入计划 Map，创建时取出、强转、再删除。本批移除该通道，日期和时间不再往返字符串转换。
- 原 `createTask` 九个参数减少到六个；时间字段集中在单次发生中。取消为了传内部字段而复制整份计划，安排的 `allowLate`、`onlyAbnormal` 和人员模式覆盖只影响任务快照，不修改原计划。
- 免检从数据库映射、生成缓存到匹配/批准信息复制均使用明确类型。沿用已有查询及更新 SQL，条件、绑定参数与排序不变；没有新建同义 CRUD、数据访问框架或表实体迁移。
- 日常生成仍先查一次免检，旧班次也保留这一读取行为。重点 MySQL 用例以真实 Repository spy 核对每轮仅调用一次免检查询；未统计整轮全部 SQL，也未做吞吐或性能提升结论。
- 安排定义和既有人员解析仍使用现有 Map 契约；`_activeIds`、`_teams` 保留在原人员解析边界。本批不是整个点巡检模型的类型化完成声明。
