# 维修报修审批接入

状态：已实现；后端隔离测试、配置页面及本地迁移已验证，验证范围见文末。

## 已确认范围

审批流程平台同时支持领料申请和维修报修审批，复用现有Flowable、公司模板、设计器与审批记录。维修审批位于报修提交之后、派工之前；维修处理结束后的验收保持原业务语义，不默认替换成新流程。

2026-10-30用户确认：各公司自行启用维修报修审批；启用后必须存在有效模板，否则阻止提交报修。未启用公司继续原报修路径。审批功能启用与模板临时停用需要区分，不能因为找不到模板而自动免审批。

## 实施交互

启用公司：提交报修 → 审批中 → 审批通过 → 待派工 → 原接单、处理和验收流程。驳回／撤回沿用已有领料审批机制：退回报修人，修改后重新提交并从最新生效模板开始新一轮；历史版本及记录保留。没有增加维修完成验收审批。

流程分支由管理员配置。优先开放可靠的现有字段：报修人、工单公司／部门、设备、设备分类、故障类型、故障等级。预计维修金额、实际维修金额没有确认数据来源，不擅自加入可用变量。

## 已确认的计时口径

用户已确认：等待派工／接单提醒从审批通过后开始计时。reportedAt保留真实报修时间，新增approval_ready_at记录允许进入派工的时间；无需审批的新报修以报修时间起算。审批中与退回待提交时不催派工或接单。

## ENG-44～ENG-51数据库审查

- wf_binding新增requires_approval，区分公司业务审批开关与既有模板enabled状态，按已有租户／公司／业务唯一键查询并发控制。维修首次发布不自动启用公司审批；领料保留原语义。
- eam_repair_order新增approval_gate（LEGACY历史、EXEMPT提交时无需审批、REQUIRED必须审批）和approval_ready_at（DATETIME(3)，空表示尚未放行）。工单状态与工作流实例状态分别承担业务与审批职责，不新增JSON主状态。已审批标记只能由当前有效实例结果确认。
- wf_todo新增source_kind区分维修与库存待办表，精确关闭原关联记录，保留已有任务／待办关联。使用现有雪花ID、租户条件和索引，不合并业务主表或待办主表。
- 新增V116；原数据默认LEGACY，已有wf_todo默认INVENTORY；不重跑历史审批。主要查询沿用工单主键、wf_instance业务轮次唯一键和wf_binding公司业务唯一键，不新增低选择性状态索引。

## 已实现与验证

- 公司设置入口位于审批流程列表的“报修审批设置”。新建模板可选择“维修报修”；发布维修模板不会自动启用公司审批。公司开关保存校验发布权限、公司范围及绑定行版本，模板停用不改变公司审批要求。
- 新增RepairApprovalService与业务适配器。公司及报修人从后台设备、登录身份取得；报修记录、条件快照与引擎实例共用事务。审批通过记录独立放行时间，真实报修时间不变。
- 报修人可按报修权限编辑本人退回的待提交单，不要求额外获得全局编辑权限。审批通过后不可直接修改报修内容。通过更换设备跨公司转入需审批公司会被阻止，不能沿用免审批资格绕过审批。
- 维修待办使用eam_repair_inbox，wf_todo以source_kind精确关联；审批结束只关闭对应审批任务。驳回／撤回生成报修人的待修改待办，重提后关闭；通过生成结果通知。消息接入现有公共发送机制。
- 抽取WorkflowApproval公共组件，领料与维修详情共同使用。维修变量覆盖人员、公司、部门、设备、分类、故障类型及故障等级；无物料明细的业务不展示明细试算和集合条件。
