## 范围与验收

| 场景 | 实现与职责 | 验收条件 |
|---|---|---|
| 普通文本包含文件 UUID | MaintenanceListRepository.referencesFile 在原授权选择上匹配真实附件字段 | 备注、处理说明、文件名不能授予下载权 |
| 新增附件关联 | MaintenanceValidationService 在原保存事务内检查当前租户文件、上传者/已有可见关联及 ID/URL 一致性 | 无权文件不能先挂到自己单据再下载；图片格式与存在性错误顺序保留 |

| 多项目与补生成 | MaintenanceProjectService 当前调用内按标准 ID 复用读取和项目索引；MaintenanceGenerationService 将稳定事实读取移出发生循环 | 保留项目顺序/复合键/旧键/去重/类型和查看校验；日期、游标、重复运行与逐任务副作用不变 |

## 设计与兼容

- 不增加接口、Helper、缓存框架、HTTP DTO 或新的持久化模型；私有 StandardProjects 只把一次读取的标准名称及旧项目快照索引聚合在一起。项目 Map 仍为原快照协议边界，不宣称固定接口类型治理已完成。
- 不跨请求缓存，不修改状态机、事务或锁顺序。保养计划/安排锁与逐任务编号、上次结果预填、事件/通知/游标写入保持原路径。未到生成日不新增设备/项目读取。
- 附件查询是授权视图、关系表与历史 JSON 指定路径的复合只读查询，BaseMapper 单表操作不能表达；复用现有列表 SQL 执行器和授权谓词，值全部绑定。禁止全文包含匹配。
- URL 是旧接口真正下载的对象；旧记录 URL 为空时才使用附件字段 ID。显式 ID 与 URL 不同的新引用拒绝。计划头没有附件字段，其普通文本不能用于授权。
- HTTP 路径、返回字段/类型、文件传输、分页/导出不变。拒绝原来错误放行的引用是本次安全修复；上传者本人、已有可见关联及租户边界保留。
- 无迁移、回填或数据清理；回退无需迁移，但不得把重新开放 UUID 全文授权当作安全回退。用户已有四项未提交改动未纳入。
